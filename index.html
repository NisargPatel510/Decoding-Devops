VERSION CONTROL + COLLABORATION

Git + GitHub

Git records source-code changes. GitHub hosts Git repositories and adds collaboration features such as pull requests and code review.

01

Repository

A project workspace containing files, history and Git metadata.

02

Commit

A recorded snapshot of staged changes with a message.

03

Branch

An independent line of development used for features or fixes.

04

Pull Request

A GitHub mechanism for proposing and reviewing changes before merging.

05

Clone

Creates a local copy of a remote repository, including its history.

06

Merge

Combines changes from one branch into another.

👥 Team projects

Developers work on branches and integrate changes through pull requests.

🔎 Code review

Teammates discuss and review changes before they reach the main branch.

🕘 History

Commits provide a traceable record of what changed and when.

🌍 Collaboration

A remote repository allows contributors to work from different machines.

Initialize

Start Git tracking.

git init
Stage

Stage all current changes.

git add .
Commit

Save a snapshot.

git commit -m "message"
Push

Upload commits to GitHub.

git push origin main
Branch

Create and switch branches.

git switch -c feature-name
Pull

Get remote changes.

git pull origin main
MINI LAB

Publish a local project

  1. Create a small project and run git init.
  2. Use git status to inspect changes.
  3. Stage and commit the files.
  4. Create a GitHub repository and add it as a remote.
  5. Push the main branch.
💡 Never commit passwords, API keys or other secrets.
🐳
CONTAINERIZATION

Docker

Docker packages an application and its dependencies into a container image so it can run consistently across environments.

01

Image

A read-only template used to create containers.

02

Container

A running, isolated instance created from an image.

03

Dockerfile

A text file containing instructions for building an image.

04

Registry

A service that stores and distributes container images.

05

Volume

Persistent storage managed separately from a container.

06

Port mapping

Connects a host port to an application port inside a container.

📦 Consistency

Package dependencies with the application.

🚀 Deployment

Start applications from known images quickly.

🧪 Testing

Run isolated and repeatable environments.

☁️ Cloud workloads

Use the same container artifact across platforms.

Build image

Build from Dockerfile.

docker build -t myapp .
Run container

Run and publish port 8080.

docker run -d -p 8080:80 myapp
List containers

Show running containers.

docker ps
List images

Show local images.

docker images
Stop

Stop a running container.

docker stop CONTAINER_ID
Logs

Inspect container output.

docker logs CONTAINER_ID
MINI LAB

Containerize a static website

  1. Create index.html.
  2. Write a Dockerfile using a web-server image.
  3. Build the image.
  4. Run it with a host-to-container port mapping.
  5. Open the mapped port in a browser.
💡 Image = packaged blueprint. Container = running instance.
☸
CONTAINER ORCHESTRATION

Kubernetes

Kubernetes automates deployment, scaling and management of containerized workloads across a cluster.

01

Cluster

A set of machines managed together by Kubernetes.

02

Node

A worker machine where Pods run.

03

Pod

The smallest deployable Kubernetes unit containing one or more containers.

04

Deployment

Describes desired application state and manages replicated Pods.

05

Service

Provides a stable network endpoint for a set of Pods.

06

Namespace

A logical boundary for grouping Kubernetes resources.

📈 Scaling

Increase or decrease application replicas.

🩹 Self-healing

Replace failed Pods to approach the desired state.

🔄 Rolling updates

Progressively release new application versions.

🌐 Service discovery

Provide stable communication endpoints for workloads.

Cluster info

Show cluster information.

kubectl cluster-info
List Pods

Show Pods in the current namespace.

kubectl get pods
Apply YAML

Create or update resources.

kubectl apply -f deployment.yaml
Deployments

Inspect Deployments.

kubectl get deployments
Services

Inspect Services.

kubectl get services
Describe

View resource details and events.

kubectl describe pod POD_NAME
MINI LAB

Deploy a containerized website

  1. Make the Docker image available to Kubernetes.
  2. Create a Deployment YAML.
  3. Create a Service YAML.
  4. Apply the manifests with kubectl apply -f.
  5. Inspect Pods, Deployment and Service status.
💡 You declare the desired state; Kubernetes works toward it.
J
CI/CD AUTOMATION

Jenkins

Jenkins is an automation server used to create pipelines that build, test and deliver software.

01

Job

A configured Jenkins task that performs an automation process.

02

Pipeline

A sequence of automated stages representing software delivery.

03

Jenkinsfile

A versioned file defining a Jenkins Pipeline as code.

04

Stage

A logical phase such as Build, Test, Package or Deploy.

05

Agent

An execution environment where Jenkins runs pipeline work.

06

Plugin

An extension that adds integrations or capabilities to Jenkins.

🔨 Continuous Integration

Build and test changes automatically after source updates.

🚢 Continuous Delivery

Automate packaging and delivery after validation.

🧪 Automated testing

Run repeatable tests as part of the pipeline.

🔗 Tool integration

Connect source control, Docker and deployment systems.

JENKINSFILE CONCEPT

Pipeline as code

pipeline {
  agent any

  stages {
    stage('Build') {
      steps { echo 'Building...' }
    }

    stage('Test') {
      steps { echo 'Testing...' }
    }

    stage('Docker') {
      steps { echo 'Building image...' }
    }

    stage('Deploy') {
      steps { echo 'Deploying...' }
    }
  }
}

MINI LAB

Create a simple CI pipeline

  1. Create a Jenkins Pipeline job.
  2. Connect it to the GitHub repository.

  5. Later add Docker build and Kubernetes deployment stages.
💡 Pipeline as code makes the delivery process versionable.
